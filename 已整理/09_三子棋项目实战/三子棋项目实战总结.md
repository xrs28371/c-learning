# 三子棋项目实战总结

## 项目是什么

3×3 三子棋，玩家与电脑对弈。玩家落子用 `*`，电脑落子用 `#`，先连成一行、一列或一条对角线者胜，棋盘下满且无人连线则平局。

## 文件分工

- `game.h`：功能函数声明与常量定义，`ROW`、`COL` 均为 3。
- `game.c`：功能函数的具体实现。
- `三子棋项目实战.c`：游戏整体逻辑与菜单循环。

三份文件在 Drive 里的更新时间为 2026-10-26 21:07–21:08，GitHub 提交前已用 gcc 在 Linux 下编译通过，输入 `0` 退出路径正常。

## 函数清单

- `init_board`：把棋盘全部初始化为空格 `' '`。
- `print_board`：打印棋盘，行与行之间用分隔行隔开，函数名已统一为 `print_board`（此前主文件与头文件/实现不一致的问题已解决）。
- `palyer_move`：玩家落子。输入为 1–3 的行列坐标（以空格分开），会校验坐标是否合法、该位置是否已被落子，不合法或已落子会提示并要求重新输入。
- `pc_move`：电脑落子。用 `rand() % row`、`rand() % col` 随机选空位落子。
- `is_win`：判胜负。按行、列、两条对角线检查是否连线，返回落子字符表示胜者；棋盘下满且无人胜返回 `'Q'` 表示平局；无人胜且棋盘未满返回 `'C'` 表示继续。
- `is_full`：仅在 `game.c` 内部使用的 `static` 函数，判断棋盘是否已满，供 `is_win` 判断平局时调用。

## 对局流程

1. 主菜单：`1` 开始游戏，`0` 退出。
2. 初始化空棋盘并打印。
3. 循环：玩家落子 → 打印棋盘 → 判胜负；若未分胜负，电脑落子 → 打印棋盘 → 判胜负。
4. 循环结束时按返回值打印“玩家赢了”“电脑赢了”或“平局”。

## 学到的关键点

- 多文件项目分工：头文件只做声明与常量，`.c` 文件做实现，主文件做流程控制。
- `static` 函数只服务于本文件，`is_full` 不需要也不应该暴露给其他文件。
- 胜负判断要先排除空格：三个格子相同且不为空格才算连线，否则空棋盘一开始就会被误判。
- 随机落子需要先用时间做种子，否则每次运行的电脑落子序列会相同。

## 原样保留的小问题（未擅自改代码）

- `is_win` 里第二条对角线的判断写的是 `board[0][0] != ' '`，而不是 `board[0][2] != ' '`。当左上角为空、反对角线已连线时，这条分支可能漏判，需要后续自己改掉。
- `game()` 开头又调用了一次 `menu()`，所以选 `1` 开始后菜单会多打印一次，不影响对局。
- 原代码拼写原样保留：`palyer_move`、`1.paly`，改的时候要三处一起改（`game.h`、`game.c`、主文件），只改一处会编不过。

## 编译方式

Linux 下示例：

```sh
gcc "三子棋项目实战.c" game.c -o tictactoe
```

Windows 下按原工程用 VS 编译即可，头文件里的 `_CRT_SECURE_NO_WARNINGS` 是为 VS 的 `scanf` 警告准备的。
